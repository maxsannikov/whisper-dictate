# Whisper Dictate: горячие клавиши, установка и запуск

Краткая инструкция для openSUSE Tumbleweed и KDE Plasma 6. Команды ниже показывают установленный путь `$HOME/.local/bin/whisper`; параметры конфигурации диктовки берутся из `$HOME/.config/whisper-dictate/config.json`.

## Общая панель настроек

Пункт **«Настройки»** открывает общую панель. В разделах
**Транскрибация** и **Корректор** показаны порядки сервисов и локальных моделей;
подписи указывают, какая очередь к чему относится. В Cloudflare статус
учётных данных, usage-счётчики и расчётный остаток находятся во вложенной
вкладке **«Учётные данные»**. Заполненность credentials, использование и
последняя попытка Cloudflare разнесены по рамкам в порядке **Учётные данные →
Использование → Последняя попытка Cloudflare**; индикатор заполненности показан
один раз checkbox-ом. Там же доступны дневные
запросы/успехи/ошибки и безопасный итог/время последней Cloudflare-попытки.
Эти данные обновляются при переходе на вкладку. Вложенные вкладки Whisper,
Корректор и Учётные данные имеют иконки. Для OpenRouter, Codex и Claude
usage-блоки также показывают локальные данные; квоты и остаток без доступного
источника отмечены как неизвестные.

Страница **Qwen** стоит сразу после **Корректора**. В строке локального
корректора в очереди коррекции есть кнопка перехода к этой странице. Иконки
навигации вкладок имеют размер 32 px, их оттенок сохранён; названия отделены
от иконок отступом. **Отмена** закрывает панель и
восстанавливает конфигурацию, которая была при её открытии; **Применить**
оставляет изменения.

Заголовки очередей и блоки «Порядок локальных моделей» имеют отдельный отступ
от края страницы. Блок моделей размещён вне списка сервисов, поэтому наведение
на него не подсвечивает всю рамку синим.

Настройки локального корректора находятся в разделе **Qwen**: выбор локальной
модели, prompt, автозамены, GPU offload, контекст, потоки, timeout, keep-alive,
temperature, VRAM и выгрузка. Приглушение и восстановление громкости находятся
в **Транскрибация**. Уведомление завершённой диктовки называет backend и модель,
которые вернул daemon для этого задания.

## Горячие клавиши KDE

Откройте **Параметры системы → Клавиатура → Комбинации клавиш**. Чтобы создать свою команду, нажмите **Добавить → Команду или скрипт…**, задайте имя, команду и сочетание, затем примените изменения. Для существующего действия найдите его через поиск, выберите сочетание, нажмите поле назначения клавиш, введите комбинацию и нажмите **Применить**. В Plasma 6 старый модуль KHotKeys «Пользовательские комбинации клавиш» удалён, поэтому его инструкции из старых руководств не подходят.

На этой установке в `~/.config/kglobalshortcutsrc` записаны `Meta+Shift+S` для fast-v2, `Meta+Shift+D` для medium-v2 и `Meta+Shift+F` для full-v2. Также остались привязки `Meta+Shift+F` и `Meta+Shift+D` к старым целям `~/bin/whisper-dictate-fast` и `~/bin/whisper-dictate`; эти файлы и `~/bin/khotkey-run` сейчас отсутствуют. Такие привязки нужно удалить или переназначить. Проверьте конфликты сочетаний перед сохранением.

Live-запись общая для всех профилей: пока запись активна, другое профильное сочетание не запустит вторую запись и покажет, какой профиль нужно остановить. Остановить текущую запись можно тем же сочетанием, которым она была начата; после этого выберите другой профиль.

### Профили и действия
| Назначение | Команда | Профиль и результат |
|---|---|---|
| Быстрая live-диктовка | `$HOME/.local/bin/whisper/whisper-dictate-fast-v2` | Быстрый, `small`, CUDA `int8_float16`; записывает микрофон и передаёт распознанный текст в выбранный режим результата. |
| Средняя live-диктовка | `$HOME/.local/bin/whisper/whisper-dictate-medium-v2` | Средний, `medium`, CUDA `int8_float16`. |
| Полная live-диктовка | `$HOME/.local/bin/whisper/whisper-dictate-full-v2` | Медленный/полный, `large-v3`, CUDA `int8_float16`. |
| Обычная live-диктовка | `$HOME/.local/bin/whisper/whisper-dictate-v2` | Текущий профиль из пользовательского `config.json` (по умолчанию в скрипте `large-v3`). |
| Один аудио/видеофайл | `$HOME/.local/bin/whisper/whisper-dictate-v2 --file "/путь/к/файлу"` | Файл обрабатывается выбранным профилем, без захвата микрофона. |
| Несколько файлов (batch) | В трее: **«Распознать файлы…»**, выберите файлы и подтвердите. Поддерживаются распространённые аудиоформаты, включая MP3, WAV, M4A/AAC, FLAC, OGG/Opus, WMA, AIFF, AMR, AC3, DTS и другие, а также видео MP4, MKV, AVI, MOV, WebM, WMV, MPEG, 3GP, TS/MTS, VOB и другие. Для видео требуется `ffmpeg`; чтение конкретного кодека зависит от сборки FFmpeg. Внутренний запуск одного элемента: `$HOME/.local/bin/whisper/whisper-dictate-v2 --file "/путь/к/файлу" --batch-id "ID_ЗАДАНИЯ" --output "/путь/к/результату.txt"` | Tray может запустить несколько элементов batch, но daemon сериализует ASR и correction по одной FIFO очереди и одному worker. Источник `file`; ID и пути результатов создаёт tray. |
| YouTube, RuTube, VK | Отдельной пользовательской CLI-команды нет: в трее выберите **«Распознать видео по ссылкам…»** и вставьте по одной ссылке на строку. Внутренняя команда обработки передаёт `WHISPER_JOB_SOURCE=youtube`, `rutube` или `vk` в зависимости от allowlist домена. | Tray загружает/читает аудио из кэша и запускает общий обработчик; нужны сеть и `yt-dlp`. Поддержка конкретного видео зависит от extractor, доступности ролика, DRM, региона и требований авторизации/cookies. |

Для batch ссылок метаданные запрашиваются отдельно по каждой ссылке. Сбой, timeout или дубликат показывается с URL и не останавливает остальные элементы. Успешные элементы сохраняют порядок ввода. URL обрабатываются `yt-dlp`, аудио и транскрипция остаются локальными; удалённые providers к ссылкам и локальным файлам не применяются.

Кнопка **«Новая транскрибация»** запускает обычную live-диктовку с текущими настройками. В shell команда с `$HOME` должна вводиться в кавычках или без кавычек вокруг отдельного пути; не подставляйте путь к аудио в команду через shell-конкатенацию.

Пункт **«Запустить корректор»** берёт текст из буфера обмена, проводит его через
включённые вручную сервисы коррекции и копирует результат обратно в буфер.
Маршруты для этого режима настраиваются отдельно от коррекции сразу после live-
транскрибации на вкладке **Корректор → Порядок**. Текст не записывается в логи
или метрики.

Раздел настроек **«Справка»** содержит руководство и историю изменений.
**«Диагностика»** содержит статистику, историю транскрибации и журналы. Оба
раздела можно открыть напрямую кнопками в окне **«О приложении»**.

Cloudflare и OpenRouter открываются из общей панели **«Настройки»**; их отдельные пункты удалены из tray-меню. Во вкладке Cloudflare → **«Учётные данные»** находятся учётные данные, usage и последняя попытка: отдельно результат Whisper и корректора, безопасная категория ошибки или локальный fallback (GPU/CPU) и местное время. Ошибки `429`, `401/403`, сеть, тайм-аут и некорректный ответ объясняются без вывода сырого ответа. File/batch/YouTube/RuTube/VK остаются локальными. Строка расхода Cloudflare — оценка за UTC-день, а расчётный остаток не подтверждает фактическую квоту или доступность сервиса.

В главном меню выберите **«Статистика за сегодня»**, чтобы увидеть таблицу попыток ASR и коррекции по сервисам/моделям: всего, успешно, неуспешно и время обработки в пересчёте на минуту аудио. Показатель считается как суммарное время успешных попыток, делённое на суммарную длительность их аудио, поэтому учитывает разную длину записей. Например, **8 с/мин аудио** означает около 8 секунд обработки на одну минуту записи. Это нормализованное время: `время обработки ÷ длительность аудио × 60`. RTF — сокращение от *real-time factor*, отношение времени обработки к длительности аудио; например, `RTF 0,5` означает 30 секунд обработки на минуту записи. В таблице это показано как `30 с/мин аудио`. Фильтры над таблицей позволяют выбрать этап (Whisper/ASR или коррекция) и сервис (OpenRouter, локальные модели, Cloudflare, Groq или Google Gemini). Учёт ведётся по UTC-дню. Новые метрики фиксируют модель, сервис, результат, категорию ошибки и длительность этапа; аудио, распознанный текст и пути к файлам в таблицу попыток не записываются. Старые записи отображаются по доступным полям и могут не содержать длительности отдельных неуспешных попыток.

Кнопка **«Обнулить статистику»** начинает новый отсчёт для таблицы одним нажатием. Она сохраняет исходный журнал метрик и данные, используемые для расчёта квот; в таблице учитываются попытки, записанные после сброса.

## Установка и безопасное обновление

1. Установите системные зависимости: `python3`, `pip3`, `git`, `ffmpeg`, `libsndfile`; GTK3/AppIndicator нужны трею, `yt-dlp` — функции YouTube. Для перечисленных пакетов в документации проекта используется `sudo zypper install python311 python311-pip git ffmpeg libsndfile1`.
2. Клонируйте публичный репозиторий `https://github.com/maxsannikov/whisper-dictate.git`, перейдите в каталог `whisper-dictate` и запустите `./install.sh`. Установщик копирует скрипты и systemd units, ставит Python-зависимости и включает службы. Перед запуском просмотрите `INSTALL.md` и `REQUIREMENTS.md`; установщик вносит системные изменения.
3. Проверка: `./verification/check-installation.sh`, затем `systemctl --user status whisper-daemon.service whisper-tray.service`. Самостоятельно проверьте наличие `~/.local/share/doc/whisper-dictate/guide.md` и `CHANGELOG.md`, а также меню трея → **Помощь → История изменений**.
4. Для обновления проверьте локальные изменения, выполните `git pull --ff-only origin main`, затем снова запустите `./install.sh`; не перезаписывайте вручную пользовательские настройки в `~/.config/whisper-dictate/` и данные в `~/.cache/whisper-dictate/`.

Документация: `INSTALL.md`, `REQUIREMENTS.md`, `systemd/README.md` в корне клонированного репозитория.

## Автозапуск и ручной запуск

Демон — пользовательская служба systemd без привязки к видимости графического интерфейса. Tray — пользовательская служба, привязанная в unit к `graphical-session.target`, и ему нужен активный графический сеанс.

```bash
systemctl --user list-unit-files 'whisper-*'
systemctl --user status whisper-daemon.service
systemctl --user status whisper-tray.service
systemctl --user enable whisper-daemon.service
systemctl --user enable whisper-tray.service
systemctl --user start whisper-daemon.service
systemctl --user start whisper-tray.service
```

`enable` сохраняет автозапуск, `start` запускает сейчас; для перезапуска используйте `systemctl --user restart ИМЯ.service`. Проверяйте отдельно: `systemctl --user is-enabled whisper-daemon.service whisper-tray.service` и `systemctl --user is-active whisper-daemon.service whisper-tray.service`. В этой установке имеются оба user units; файл desktop/autostart для Whisper Dictate не обнаружен, поэтому способ через KDE Autostart здесь не подтверждён и не описывается как рабочий.

Логи: `journalctl --user -u whisper-daemon.service -n 100 --no-pager` и `journalctl --user -u whisper-tray.service -n 100 --no-pager`.

## Диагностика

- **Клавиша не действует:** откройте «Параметры системы → Клавиатура → Комбинации клавиш», найдите дубликаты и конфликтующие привязки; проверьте, что команда существует и исполняема. Записанные старые цели `~/bin/whisper-dictate*` на этой системе отсутствуют.
- **Нет значка трея:** войдите в графический сеанс; проверьте `systemctl --user status whisper-tray.service`, затем его журнал. Убедитесь, что доступны GTK3 и AppIndicator и запущен пользовательский bus.
- **Ошибка демона:** проверьте `systemctl --user status whisper-daemon.service`, журнал, наличие исполняемого `~/.local/bin/whisper/whisper-daemon.py` и сокета `~/.cache/whisper-dictate/daemon.sock`. Не отправляйте логи, содержащие пользовательский текст или приватные пути.
- **CPU или GPU:** конфигурация задаёт `device` и `compute_type`; безопасные runtime-метаданные задания можно смотреть в `~/.cache/whisper-dictate/jobs/*.json` (поля backend/device/compute_type). CUDA-сбой может привести к fallback на CPU. Это не доказывает backend завершённого старого запуска, если его метаданные не сохранились. Не публикуйте аудио, распознанный текст, credential-файлы или токены.

## Дополнительные providers для live-диктовки

В главном меню есть пункт **⚙️ Настройки** с вкладками **Транскрибация** и **Корректор**. Модель и повторы каждого correction provider открываются отдельной кнопкой из строки провайдера; то же окно доступно из его меню сервиса. Вкладка **Транскрибация** не содержит настроек корректора. Дополнительные инструкции и таблица автозамен находятся только во вкладке **Корректор**. Для каждого удалённого провайдера задаётся от 0 до 2 дополнительных попыток; Groq Qwen и Groq GPT-OSS имеют отдельные настройки. Codex и Claude по умолчанию делают по две дополнительные попытки; прочие провайдеры сохраняют свои настройки повторов. Повторяются временные сбои и ответы, отклонённые safety guard; отмена, credentials и подтверждённые ограничения квоты не повторяются. Для Codex в списке доступны лёгкие модели GPT-6 Luna и GPT-5.6 Luna. Для Claude доступны Sonnet, актуальный alias Haiku и закреплённый Haiku 4.5; Opus исключён. У Codex есть отдельное подменю со статусом сессии, последним безопасным результатом коррекции и ссылкой на панель лимитов. Текущие остатки можно посмотреть командой `/status` в активной CLI-сессии Codex; локальная коррекция не может надёжно получить их из неинтерактивного `codex exec`. Основной prompt корректора встроен в приложение; дополнительные инструкции используются локальным корректором. Whisper/ASR получает отдельный начальный prompt и не получает эти инструкции. Явный ASR-хвост «Редактор субтитров А. Семкин. Корректор А. Егорова.» удаляется как служебные титры до коррекции; если он один в транскрипции, задача отмечается как пустая и провайдеры не вызываются. Исходный распознанный текст при этом сохраняется в приватном raw-ASR recovery. Codex — первый live-корректор по умолчанию; Claude по умолчанию выключен и доступен только при активной CLI-сессии. В настройках моделей отображается безопасный статус входа Claude, без email и содержимого credential store. Для correction CLI Claude используется `--safe-mode`, пустой список встроенных инструментов и запрет MCP tools; сессии не сохраняются. CLI не используются для ASR. Текст аудиофайлов и видео передаётся CLI-корректору только если для него включён сценарий **«Файл / видео»**.

Вкладка **OpenRouter** общей панели объединяет учётные данные, локальное дневное использование, число попыток/успехов/ошибок, базовые Free-лимиты и ссылку на Activity. В рамке **«Настройки корректора»** можно включить сервис, задать или открыть ключ, явно проверить его и настроить число повторов (0–2); каждый повтор расходует отдельный запрос из Free-квоты. Модель выбирается по недавним безопасным результатам. Вкладка Cloudflare содержит переключатели Whisper и корректора, модели и повторы. У Groq и Gemini есть независимые переключатели ASR/correction и настройки модели/повторов корректора. Ключи API задаются скрытым вводом или файлами в `~/.config/whisper-dictate/credentials/` с правами `0600`.

Общая галочка **«Использовать AI-корректоры»** находится в меню локального корректора и на вкладке **Корректор** окна настроек. Она включена по умолчанию; отключение выдаёт исходный текст ASR для live, file и batch jobs и сохраняет отдельные настройки провайдеров. При повторном включении прежние provider toggles продолжают действовать. Стрелки порядка доступны также для локального Qwen и локального ASR. Выбранная позиция задаёт приоритет, а local остаётся безопасным последним fallback в live-цепочке; файлы и batch по-прежнему используют только локальный ASR.

Live ASR chain по умолчанию: Cloudflare → включённый Groq Whisper → включённый Gemini → local FasterWhisper. Начальный приоритет live correction: Codex → Claude → Cloudflare → OpenRouter → дополнительные remote providers → local Qwen. Порядок correction и ASR хранится соответственно в `multi_provider.correction.order` и `multi_provider.asr.order`. В обоих списках local можно перемещать; когда local поставлен раньше, безопасный завершающий local fallback всё равно сохраняется. Старые конфигурации без correction списка переносят позицию Cloudflare из `cloudflare_position`. Для каждого корректора независимо настраиваются три сценария: после голосовой диктовки, по кнопке и после транскрибации аудио/видео/ссылки. Для файлов и видео используются только отмеченные провайдеры в общем порядке; цепочка останавливается на первом ответе, прошедшем проверку полноты и порядка слов. Cloudflare можно отдельно включить для файлов и видео; учитывайте применимые тариф, время обработки и квоты. ASR providers остаются доступны только live-сценарию. OpenRouter выбирает бесплатную модель по недавним безопасным результатам; без истории использует `openrouter/free`. Ошибки credentials, HTTP 401/403, подтверждённая дневная квота и отмена повторов не допускаются; это не доказывает, что текст стал точнее.

Пункт трея **«Настройки»** открывает единое окно с вкладками
**Транскрибация**, **Корректор**, Cloudflare, OpenRouter, Codex, Claude, Groq и
Gemini. Вкладки расположены вертикальным списком слева; в заголовке каждой
вкладки видны название и иконка. На вкладке **Корректор** общий переключатель AI-коррекции расположен
справа над списком моделей и провайдеров. Сервисные вкладки показывают параметры
моделей и провайдеров. Пункты настроек из меню Codex, Claude, Groq и Gemini
открывают это же окно на соответствующей вкладке; Cloudflare и OpenRouter теперь
доступны только в общей панели. Значки KDE launcher и tray
используют один общий файл микрофона. Action/Help иконки показываются в 48 px
без квадратной подложки; provider logos отображаются без фона в 48 px.

В настройках **Транскрибация** отдельные вкладки задают порядок локальных ASR-моделей
для голосовой диктовки и для файлов/видео. В списке доступны FasterWhisper
Large-v3, Large-v3 Turbo, Medium и Small, а также три варианта GigaAM. Для файлов
и видео локальный FasterWhisper Large-v3 стоит первым по умолчанию; другие модели
можно отметить и переставить для резервного порядка. Файлы и видео всегда идут
через локальные ASR-модели, независимо от live-порядка сервисов. Для локальной
коррекции доступны Qwen3.5 4B и 2B. Следующая модель пробуется при техническом
отказе, ошибке загрузки или пустом ASR-ответе; у корректора также при отклонении
результата текущей safety-проверкой. Приложение не определяет субъективную
точность по confidence и не скачивает модель при fallback. Непредустановленная
Qwen пропускается через обычный отказ Ollama. Старые настройки голоса сохраняют
свой прежний порядок; новый порядок файлов и видео начинается с Large-v3.

### Выбор локального ASR

Выбор модели и параметры находятся в **Настройки → Транскрибация → Whisper**
или **GigaAM**. При изменении выбора daemon подготавливает выбранную модель;
предыдущая ASR-модель освобождается перед загрузкой новой. На вкладке Whisper находятся стратегия качества,
beam size (целый слайдер 1–50), best-of, temperature, язык, VAD, FP16 и контекст предыдущего текста;
эти параметры относятся только к FasterWhisper. Там же можно выбрать модель:
Large-v3 — профиль с наивысшим качеством и большим расходом памяти; Large-v3
Turbo — экспериментальный вариант, качество которого отдельно не подтверждено;
Medium — промежуточный размер/скорость; Small — более компактный и быстрый
вариант с меньшим запасом качества. Выбор FasterWhisper сохраняется в `model`.

На вкладке GigaAM выбираются модель и связанное с ней устройство. `e2e_rnnt`
работает через PyTorch worker на CPU; `e2e_ctc` использует ONNX Runtime CUDA
FP32 и декодирование с пунктуацией/нормализацией; `ctc` — базовый ONNX CTC
результат на CUDA FP32. GigaAM не использует параметры Whisper. Длинные записи
обрабатываются окнами до 24 секунд с overlap 1 секунда; размер окон фиксирован
backend-ом и отдельно не настраивается. Выбор хранится в `asr_backend`.
GigaAM работает с закреплёнными локальными весами; GPU-модели устанавливаются
отдельно скриптом `~/.local/bin/whisper/install_gigaam_onnx_models.sh all`.
FasterWhisper остаётся backend-ом по умолчанию.
В трее команда **«Выгрузить все модели»** освобождает загруженные приложением
модели FasterWhisper, GigaAM и все настроенные локальные модели Qwen. Команда
ждёт завершения уже выполняемых заданий и только затем освобождает память.
Кнопки **«Выгрузить Whisper»** и **«Выгрузить GigaAM»** находятся на их
вкладках настроек; для Qwen отдельная кнопка остаётся на вкладке корректора.
Если локальный корректор выключен, Qwen не загружается даже после ошибки
удалённых корректорных провайдеров. Если он включён, Qwen загружается при
выполнении локального этапа коррекции.
Во время задания строка статуса показывает фактически использованные модель и
устройство; если выбранная GigaAM не загрузилась или завершилась ошибкой, статус
сообщает о переходе на FasterWhisper и безопасную категорию причины. GigaAM GPU
и локальный GPU корректор работают последовательно, чтобы не занимать VRAM
одновременно.

Чтобы вручную проверить локальный путь для live-диктовки, выберите GigaAM, затем
отдельно выключите **Cloudflare → Использовать Cloudflare для Whisper**. Этот
переключатель управляет ASR; настройка Cloudflare-корректора независима. После
этого выполните короткую диктовку и проверьте строку активного задания: ожидается
**GigaAM-v3 e2e_rnnt · CPU**. Содержимое диктовки для проверки не нужно сохранять.
Если Cloudflare ASR включён, live-маршрут может выбрать его раньше локальной
модели. Обработка файлов и batch/video остаётся local-only.

Файлы и задания по ссылкам читают выбранный локальный `asr_backend` из текущего
`~/.config/whisper-dictate/config.json` при поступлении каждого задания. После
переключения GigaAM/FasterWhisper следующие задания используют новый выбор;
Cloudflare и удалённые корректорные backend для этих источников не включаются.
Если daemon недоступен, direct fallback не запускает другую ASR-модель молча:
для выбранной GigaAM задание завершится с понятной ошибкой, поскольку direct
режим поддерживает только FasterWhisper.

Daemon использует две FIFO очереди: один worker последовательно выполняет ASR,
второй последовательно выполняет коррекцию. Если локальная GigaAM уже загружена
на CPU, она может распознавать следующее задание, пока корректор завершает
предыдущее. Для FasterWhisper/GPU, удалённого ASR, первой загрузки GigaAM и
перехода на FasterWhisper fallback этапы остаются последовательными, чтобы не
выгружать модель во время inference и не создавать конфликт за VRAM. Ответ
каждого задания и его метрики завершаются только после коррекции; время ожидания
очереди коррекции учитывается отдельно. В строке состояния `модель — этап ·
backend` описывается собственный фактический этап этого задания. При выборе GigaAM надпись
`large-v3 · локальный GPU` во время запуска была ошибочной: до исправления
metadata временно брала FasterWhisper model/device до загрузки GigaAM.

Cloudflare-корректор также умеет ранжировать отдельные модели по недавним безопасным результатам: Qwen3 30B A3B FP8, GLM-4.7-Flash и GPT-OSS-20B. На вкладке Cloudflare → **«Корректор»** пункт **«Автоматически по статистике»** выбирает сначала модель с лучшей сглаженной долей принятых ответов за последние 30 дней, затем следующие модели; модели без истории пробуются для сбора данных. Можно вручную закрепить любую модель первой, а оставшиеся следуют по статистике. После неуспешного ответа разрешено от 0 до 2 дополнительных запросов, каждый к другой модели; первый ответ, прошедший неизменённую проверку полноты/сохранения слов, завершает коррекцию. 401/403, 429, credentials error и исчерпание дневной квоты повторно не отправляются. Каждая попытка отдельно учитывается в существующем лимите нейронов. В метриках сохраняются только модель, исход, длительность и безопасная категория ошибки — не текст транскрипции или ответа.

Дневные блокировки действуют отдельно для каждого provider и сохраняются между перезапусками. OpenRouter перед каждым бесплатным запросом атомарно проверяет локальный UTC-счётчик; после 50-го вызова 51-й запрос не отправляется, и correction переходит к Cloudflare, если его оценочный лимит доступен. Для Cloudflare приложение заранее резервирует оценочный расход нейронов на ASR или correction и не отправляет запрос, если он превысит остаток базовых 10 000 нейронов в день. Это локальная оценка; внешнее использование аккаунта может исчерпать квоту раньше. Подтверждённая ошибка Cloudflare 3036 также блокирует только Cloudflare; код 3040 остаётся временной ошибкой. Все дневные блокировки и счётчики сбрасываются в 00:00 UTC, то есть в 03:00 по Москве.

Для коррекции локальные метрики фиксируют выбранный OpenRouter upstream model из поля `model` ответа, когда сервер его вернул. Если response parser не получает непустой текст, категория уточняет проблему (`missing_choice`, `missing_content`, `non_string`, `empty`). Если ответ есть, но он отклонён сохранным guard, метрика различает длину, покрытие/порядок слов, хвост и некорректный формат; сами тексты и prompt не записываются. Подробнее о выбранной модели смотрите OpenRouter Activity: [официальная документация Free router](https://openrouter.ai/openrouter/free) и [Chat Completions API](https://openrouter.ai/docs/api/api-reference/chat/create-a-chat-completion).

Новые providers применяются только к точному source `live_dictation`. Файлы и batch/video jobs остаются локальными. На вкладке OpenRouter общей панели показываются локально учтённые вызовы, попытки/успехи/ошибки и приблизительный остаток от базового лимита 50 запросов в день. Для этого приложения предел остаётся 50, даже если аккаунт с $10+ credits допускает до 1 000 запросов. Счётчик не учитывает другие клиенты; фактический остаток аккаунта доступен в OpenRouter Activity. Для free-моделей действует также лимит 20 запросов в минуту.

### Где взять Account ID и API keys

**Не отправляйте ключи в чат или промпт.** Секрет вводится только в локальный файл или скрытое поле программы. Модели уже выбраны в настройках Whisper Dictate: указанные ниже model IDs не являются вашими account IDs и вручную вставлять их в credential files не нужно.

1. **Cloudflare:** откройте **Настройки → Cloudflare → Учётные данные → Открыть файл Account ID и API token…**. В текстовом редакторе укажите `CLOUDFLARE_ACCOUNT_ID` и `CLOUDFLARE_API_TOKEN`, сохраните файл. Account ID и токен выдаются на странице Workers AI → Use REST API в [Cloudflare Dashboard](https://dash.cloudflare.com/). Токен должен иметь права Workers AI Read и Edit.
2. **Groq:** откройте отдельный пункт **Groq → Открыть файл API key Groq…** (или **Задать ключ Groq…**). Получите ключ в [Groq Console API Keys](https://console.groq.com/keys). Файл: `~/.config/whisper-dictate/credentials/groq.key`.
3. **Google Gemini API:** откройте **Другие сервисы: Google Gemini → Открыть файл API key Google…**. Создайте ключ в [Google AI Studio](https://aistudio.google.com/apikey); файл: `~/.config/whisper-dictate/credentials/google.key`. Россия не указана в [списке доступных регионов](https://ai.google.dev/gemini-api/docs/available-regions).
4. **OpenRouter:** откройте **Настройки → OpenRouter**. В рамке «Настройки корректора» используйте «Задать ключ», «Открыть файл API key» или «Явно проверить ключ». Создайте ключ в [OpenRouter Settings → Keys](https://openrouter.ai/settings/keys); файл: `~/.config/whisper-dictate/credentials/openrouter.key`.

Новые файлы создаются с правами `0600`, каталог ключей — `0700`; существующие не перезаписываются. После сохранения можно явно проверить ключ (проверяется API и список моделей, без audio/transcript). На текущей конфигурации цепочки: Cloudflare → local Whisper для ASR и OpenRouter Free → Cloudflare correction → local Qwen для коррекции. Первый безопасный корректор завершает цепочку. Если OpenRouter или Cloudflare ответ отклонён safety-проверкой, коррекция переходит к следующему этапу.

Во время активной обработки значок трея и строка задания различают фактический backend. Во время записи показываются микрофон и подпись «Запись»; название модели появляется после выбора backend. Иконки меню и providers загружаются из локального набора и не зависят от системной GTK-темы.

Для live-диктовки предусмотрено отдельное действие **«📋 Выдать исходный текст и остановить коррекцию»** в трее: оно расположено после **«Очистить зависшие задачи»**, между ними и предыдущими пунктами стоит разделитель. Когда ASR уже завершён и задание находится на коррекции, действие немедленно копирует исходный текст Whisper в clipboard и отменяет последующие попытки коррекции, не затрагивая другие задания. Для OpenRouter активный запрос запускается в отдельном процессе и завершается при отмене; поздний ответ не заменит raw ASR. Если задания ещё нет на коррекции или raw-текст пока не готов, tray сообщит об этом. Очистка/остановка всего daemon для аварийного получения текста не требуется.
